## 1. Layer Overview

The **Masarak.Infrastructure** project implements the interfaces defined in `Masarak.Application`. It is the outermost layer of the Clean Architecture regarding data access and external I/O. It handles everything related to databases (Entity Framework Core), file storage (Azure), payments (Stripe), email (SMTP), caching (Redis), AI providers (OpenAI/Gemini), and background messaging (RabbitMQ/MassTransit).

### Purpose
- **Data Persistence**: Maps Domain Entities to SQL Server tables using EF Core.
- **External Communication**: Talks to 3rd party APIs.
- **Asynchronous Processing**: Background workers and RabbitMQ consumers.

### Dependencies
- **Depends On**: `Masarak.Application`, `Masarak.Domain`
- **Used By**: `Masarak.API` (Registered in DI container via `Program.cs` / Dependency Injection Extensions).

## 3. Persistence & Database

### `Context.cs` (or `MasarakDbContext.cs`)
**Purpose**: The central Entity Framework Core `DbContext`.
- **Responsibilities**:
  - Contains `DbSet<T>` properties for every aggregate root (e.g., `Users`, `Subscriptions`, `Exams`, `Classes`).
  - Implements `OnModelCreating` where Fluent API configurations are applied (Table names, Primary/Foreign keys, constraints, and cascade delete rules).
  - Overrides `SaveChangesAsync` to automatically dispatch Domain Events via MediatR *before* or *after* committing transactions to SQL Server.

### `Seeders/DatabaseSeeder.cs`
**Purpose**: Populates the database with initial required data (Admin accounts, default Plans, Subject Categories) when the application starts in a fresh environment.

### `Migrations/`
**Purpose**: Auto-generated by EF Core Tools. Tracks schema changes across the 6 phases of development. Examples include `Phase2_AcademicCore`, `Phase4_AttendanceContentChat`.

## 4. Repositories

This folder contains the concrete implementations of the Repository interfaces. They rely on the injected `Context` to query and mutate data.

### Notable Implementations:
- **`UserRepository.cs` / `AdminUserRepository.cs`**: Handles fetching users, filtering by roles, and resolving Student Linkage Codes.
- **`ClassRepository.cs` / `SubjectRepository.cs` / `GradeRepository.cs`**: Handles Phase 2 Academic Core persistence. Includes complex includes (e.g., fetching a class with its enrolled students).
- **`ExamRepository.cs` / `StudentExamRepository.cs` / `SubmissionRepository.cs`**: Handles Phase 3 logic. `GetPendingGradingAsync` queries rely heavily on filtering exams where `Status == Pending`.
- **`AttendanceRepository.cs` / `ContentItemRepository.cs`**: Phase 4 persistence.
- **`Phase5Repositories.cs`**: Groups specific read-heavy queries required for AI analytics (e.g., aggregating student scores across a semester).
- **`ChatRoomRepository.cs` / `ChatMessageRepository.cs`**: Handles fetching paginated chat histories. 

**Performance Consideration**: Repositories in Masarak utilize `.AsNoTracking()` for read-only Queries to improve performance and avoid polluting the EF Change Tracker.

## 5. External Services & Integrations

The `Services/` directory contains concrete logic for both Application orchestration and 3rd party integrations.

### Authentication & Security
- **`AuthService.cs`**: Implements user login/registration. Integrates with password hashing.
- **`JwtService.cs`**: Uses `Microsoft.IdentityModel.Tokens` to generate JWT Access Tokens and Refresh Tokens.
- **`PasswordService.cs`**: Provides BCrypt or ASP.NET Core Identity password hashing.

### Third-Party Integrations
- **`StripeService.cs`**: Uses the Stripe.NET SDK to create Checkout Sessions, Payment Intents, and handle Webhook verifications for Subscriptions (Phase 1).
- **`AzureBlobStorageService.cs` / `LocalFileStorageService.cs`**: Implements `IFileStorageService` to upload/download files (PDFs, Videos for Phase 4) to Azure containers. Falls back to local disk during local dev.
- **`EmailService.cs`**: Uses SMTP (via MailKit or `System.Net.Mail`) to send forgot-password links and notifications.
- **`AgoraTokenService.cs`**: Generates RTC tokens for live video sessions using the Agora SDK.

### AI & Analytics (Phase 5)
- **`AiProviders.cs`**: A factory/adapter that communicates with OpenAI (GPT-4), Anthropic (Claude), or Google (Gemini) APIs.
- **`AiAnalyticsService.cs`**: Feeds student performance data to the AI Provider and parses the resulting JSON/Markdown into `WeaknessAnalysisDto`.

### Application Services (Business Logic Implementation)
*Note: In Masarak, Application-specific orchestration (like `AssessmentService.cs`, `LessonService.cs`) is implemented here in Infrastructure, although standard Clean Architecture usually places Application Service implementations in the Application layer itself. This design choice couples orchestration with Infrastructure but simplifies DI.*

## 6. Background Jobs (Hosted Services)

Located in the `Services/` folder, these inherit from `IHostedService` or `BackgroundService` to run asynchronously in the background.

- **`SubscriptionExpiryJob.cs`**: Runs daily to find subscriptions where `EndDate < DateTime.UtcNow` and marks them as Expired.
- **`ExamAutoExpireJob.cs`**: Polls active student exams. If the time limit (e.g., 60 minutes) has passed, it forcefully auto-submits the exam and triggers grading.
- **`AbsentMarkingBackgroundJob.cs`**: Runs at the end of the day to mark any student who didn't join a live session as 'Absent'.

## 7. Messaging & Consumers

Masarak uses **RabbitMQ** (via **MassTransit**) for asynchronous event-driven architecture, decoupled from HTTP request threads.

### `Phase5Consumers.cs`
- Listens for events like `ExamGradedEvent`. When an exam is graded, this consumer triggers the AI engine to generate new `ContentRecommendationDto`s in the background without blocking the teacher's grading UI.

### `Phase6NotificationConsumers.cs`
- Listens for core domain events (e.g., `SessionScheduledEvent`, `SubscriptionExpiringEvent`).
- Formats a localized message.
- Pushes the message to the Angular frontend via **SignalR** (`NotificationHub`) and saves it to the database via `NotificationRepository`.

### `PerformanceRecalculationConsumer.cs`
- Updates materialized views or aggregated tables when a new grade is submitted to keep dashboard queries extremely fast.

## 8. Configurations

Located in the `Configurations/` folder. These files use the `IOptions<T>` pattern.
- **`JwtSettings.cs`**: Maps to `"JwtSettings": { "SecretKey": "...", "Issuer": "..." }`
- **`StripeSettings.cs`**: Maps to `"Stripe": { "SecretKey": "...", "WebhookSecret": "..." }`
- **`SmtpSettings.cs`**: Mail server credentials.

*Note: These POCOs are registered in `Program.cs` via `builder.Services.Configure<JwtSettings>(builder.Configuration.GetSection("JwtSettings"));`*
